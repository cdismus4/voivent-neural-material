# VNM1 形式仕様（SPEC）— Voivent Neural Material

- 形式名：`VNM1`／形式版：`1`
- 本書の位置づけ：VNM1 形式の公開仕様。復号手順・二進レイアウト・プロファイル登録表・適合条件を、実装言語に依存しない形で定義する。本書が形式の正であり、設計書・実験記録と矛盾する場合は本書を優先する。
- 対応する決定記録：形式改訂（プロファイル拡張・格納ルール統一）は `REVISION_DECISION.md`（2026-11-18 盟友決定）に従う。

## 1. 形式の概要

- VNM1 は、ゲーム等のリアルタイム描画で使う PBR マテリアルテクスチャ一式（ベースカラー、法線、粗さ、金属度、AO）を、素材ごとに学習した小さなニューラルネット（MLP）と潜在グリッドで表現する圧縮形式である。
- マニフェストの `format` は文字列 `"VNM1"`、`version` は整数 `1`。
- 1つの素材（アセット）は **4ファイルからなるディレクトリ** で配布される：
  - `manifest.json` — メタ情報（JSON）
  - `weights.bin` — MLP の重みチャンク
  - `level-0.bin` — 潜在グリッドのチャンク
  - `tail.bin` — 遠方 mip 用の縮小テクスチャのチャンク
- 読み込み側は `tail.bin`（小さい）を先に取得して遠方表示に使い、残りを後から取得するストリーミング読み込みを前提としてよい。

## 2. プロファイル登録表

復号器の形は「プロファイル」で決まる。登録済みプロファイルは次の5つで、これ以外のプロファイル名は不正であり、読み手は明示的に拒否しなければならない（黙って近いプロファイルで復号してはならない）。

| プロファイル | 入力次元 | 隠れ幅（第1層/第2層） | 出力次元 | 1グリッドあたり潜在 ch 数 | 重み総数 | MACs/評価 |
|---|---:|---:|---:|---:|---:|---:|
| small | 12 | 16 / 16 | 8 | 4 | 616 | 576 |
| standard | 12 | 24 / 24 | 8 | 4 | 1,112 | 1,056 |
| quality | 12 | 32 / 32 | 8 | 4 | 1,736 | 1,664 |
| standard8 | 20 | 24 / 24 | 8 | 8 | 1,304 | 1,248 |
| quality8 | 20 | 32 / 32 | 8 | 8 | 1,992 | 1,920 |

- 1グリッドあたりの潜在チャンネル数 C は、プロファイルの入力次元から **C = (入力次元 − 4) / 2** で導出する。チャンク内にチャンネル数を格納することはしない（第5.2節）。
- MLP は3層の全結合層からなる（入力→隠れ1→隠れ2→出力）。隠れ層の活性化は ReLU、出力層は線形。
- 学習器の公開プリセットとして使うのは standard / standard8 / quality / quality8 の4つで、small は形式上存在するがプリセットには含めない。
- プリセットごとの潜在グリッド寸法（学習時の固定値。入力テクスチャの寸法には依存しない）：standard / standard8 は Fine 512×512・Coarse 256×256、quality / quality8 は Fine 1024×1024・Coarse 512×512。ただし復号器はアセットごとにチャンク内サブヘッダとマニフェストに記録された寸法を読むこと（プリセット値は学習側の約束であり、復号の前提ではない）。

## 3. マニフェスト（manifest.json）

JSON オブジェクト。主なフィールドは次のとおり。

| フィールド | 意味 |
|---|---|
| `format` | `"VNM1"` |
| `version` | `1` |
| `assetId` | アセットの識別文字列 |
| `sourceSize` | 元テクスチャの寸法 `[幅, 高さ]` |
| `profile` | プロファイル名（第2節の登録表のいずれか） |
| `quantization` | 潜在の量子化方式。現行は `"u8"` |
| `weightStoragePrecision` | 重みの格納精度。現行は `"f32"` |
| `computePrecision` | 計算精度。現行は `"f32"` |
| `channels` | 出力チャンネルの構成。現行は `"base3-normal2-rough-metal-ao"`（第6.4節の出力順に対応） |
| `baseColorSpace` | `"linear-srgb"` |
| `normalConvention` | `"tangent-positive-y-positive-z"`（タンジェント空間、+Y が上、+Z が手前） |
| `wrapU` / `wrapV` | 座標のラップ方式 `"repeat"` または `"clamp"` |
| `weights` | `{url, sha256, byteLength}` — weights.bin への参照と検証情報 |
| `levels` | 潜在レベルの配列。各要素は `{sourceMip, sourceSize, fineSize, coarseSize, chunk: {url, sha256, byteLength}}`（規約は第3.1節） |
| `tailFirstMip` | tail が表す最初の mip レベル（第5.3節） |
| `mipMax` | （任意）normalizedMip の正規化分母（第6.2節）。正の有限数。省略時は `max(1, tailFirstMip − 1)` とみなす |
| `tail` | `{url, sha256, byteLength}` — tail.bin への参照と検証情報 |

読み手は、各チャンクについて `byteLength` と `sha256` を実ファイルと照合してから使うこと。

### 3.1 `levels` 配列の規約

- 各要素は、元テクスチャの `sourceMip` に対応する潜在グリッド一式（Fine グリッドと Coarse グリッド、およびその格納チャンク）を表す。`sourceSize` はその mip における元テクスチャの寸法、`fineSize` / `coarseSize` はその要素の潜在グリッド寸法である。
- 要素は `sourceMip` の昇順に並べる。先頭要素は `sourceMip = 0` でなければならず、mip 0 の復号に使うのは先頭要素である。読み手は要素を配列インデックスで選択し、既定のインデックスは 0 とする。
- 形式版 1 の書き手は、要素を1つだけ（`sourceMip = 0`）書く。複数要素は将来の複数レベル配信のための形であり、現行の読み手は先頭要素のみを消費する。
- 検証は全要素に対して行う：`sourceMip` は0以上の整数、`sourceSize` / `fineSize` / `coarseSize` は正の整数の組、潜在寸法は u16 に収まること（65535 以下）、各軸で `fineSize >= coarseSize` であること。これらを満たさないマニフェストは拒否する。
- 読み手は、選択した要素の `fineSize` / `coarseSize` が、チャンク内サブヘッダ（第5.2節）の寸法と一致することを確認すること。一致しない場合は拒否する。

## 4. チャンク共通ヘッダ

すべての .bin ファイルは1つのチャンクであり、先頭16バイトが共通ヘッダである。全てリトルエンディアン。

| オフセット | 型 | 内容 |
|---:|---|---|
| 0 | u32 | マジック `0x314D4E56`（ファイル上のバイト列は `V` `N` `M` `1`） |
| 4 | u16 | 版 = 1 |
| 6 | u16 | 種別：1 = 重み、2 = 潜在、3 = tail |
| 8 | u32 | ペイロード長（バイト） |
| 12 | u32 | 予約 = 0 でなければならない |

ファイル全体の長さは 16 + ペイロード長 と一致しなければならない。マジック・版・予約・長さのいずれかが合わないチャンクは拒否する。

## 5. チャンク種別ごとのレイアウト

### 5.1 重みチャンク（種別 1、weights.bin）

- ペイロードは float32 リトルエンディアンの配列を、次の順序で連結したもの：**w1, b1, w2, b2, w3, b3**。
- 形状：w1 は [隠れ幅1 × 入力次元]、b1 は [隠れ幅1]、w2 は [隠れ幅2 × 隠れ幅1]、b2 は [隠れ幅2]、w3 は [出力次元8 × 隠れ幅2]、b3 は [8]。
- 行列は行優先（C 順序）で、行が出力ユニットに対応する（w1 の i 行目は隠れ第1層の i 番目のユニットの重み）。
- チャンク内にプロファイル名は格納されない。プロファイルはマニフェストから得る。重み総数はプロファイルごとに異なるため、ペイロード長からも一意に決まる。

### 5.2 潜在チャンク（種別 2、level-0.bin）

- ペイロードの先頭16バイトがサブヘッダである：
  - オフセット0：Fine グリッドの幅（u16）
  - オフセット2：Fine グリッドの高さ（u16）
  - オフセット4：Coarse グリッドの幅（u16）
  - オフセット6：Coarse グリッドの高さ（u16）
  - オフセット8：Fine の量子化フラグ（u8）= 1（u8 量子化を表す）
  - オフセット9：Coarse の量子化フラグ（u8）= 1
  - オフセット10〜15：予約バイト。**すべてゼロでなければならない**。非ゼロは仕様違反として拒否する（ここにチャンネル数などの情報を載せることは禁止。チャンネル数はプロファイルからの導出のみ）。
- サブヘッダに続いて Fine グリッドのデータ、その後に Coarse グリッドのデータが並ぶ。
- 各グリッドのデータは 幅×高さ×C バイト（C はプロファイルから導出するチャンネル数）。並びは行優先で、テクセル index = (y × 幅 + x)、各テクセルの中で C チャンネルが連続する（チャンネルインターリーブ）。
- 各バイトは量子化された潜在値であり、復号時に第6.5節の逆量子化で実数に戻す。

### 5.3 tail チャンク（種別 3、tail.bin）

- ペイロードの先頭16バイトがサブヘッダである：
  - オフセット0：tail の幅（u16）
  - オフセット2：tail の高さ（u16）
  - オフセット4：tail が表す最初の mip レベル（u8）
  - オフセット5：チャンネル数（u8）= 8
  - オフセット6：形式（u8）= 1（u8 unorm）
  - オフセット7〜15：予約バイト。すべてゼロでなければならない。
- 続くデータは 幅×高さ×8 バイトの u8 テクスチャで、チャンネル順は第6.4節の出力順（ベースカラー RGB、法線 X、法線 Y、粗さ、金属度、AO）、並びは行優先・チャンネルインターリーブ。
- tail は、元テクスチャ一式を縮小した通常の8チャンネルテクスチャであり、遠方表示で MLP 復号の代替に使う。生成方法は次のとおり（書き手の約束）：
  1. **寸法と mip**：tailFirstMip は、元テクスチャを繰り返し 1/2 にしたとき、最大辺が16以下になる最初の mip レベルである。各軸の寸法は `max(1, floor(元寸法 / 2^tailFirstMip))` とする。
  2. **フィルタ**：面積重み付きボックスフィルタ。出力テクセル (tx, ty) は元テクスチャ上の矩形 `[tx・W/tw, (tx+1)・W/tw) × [ty・H/th, (ty+1)・H/th)`（W, H は元寸法、tw, th は tail 寸法）に対応し、各元テクセルの寄与はその矩形との重なり面積に比例する。合計を矩形の面積 `(W/tw)・(H/th)` で割ったものが平均値である。出力グリッドは元テクスチャ全体を過不足なく分割するため、端でのラップやクランプは発生しない。縮小率が整数でない場合も、端数面積の重みでそのまま扱う。
  3. **値の空間**：平均は、元テクスチャの値そのもの（ベースカラーは線形値、スカラーは線形のデータ値）に対して行う。色空間の変換は行わない。
  4. **法線の扱い**：法線だけは xy の単純平均をしない。元テクセルごとに、まず第6.4節の法線再構成と同じ手順（xy を [−1, 1] にクランプ → `nz = sqrt(max(0, 1 − nx² − ny²))` → 単位長に正規化）で3次元ベクトルを再構成し、そのベクトルを面積重みで平均する。平均ベクトルは単位長に正規化し直す（長さが0の場合は正規化しない）。格納するのは nx, ny のみで、nz は格納しない（読み手が再構成する）。
  5. **量子化のタイミング**：平均と正規化は浮動小数点のまま行い、u8 への量子化は最後に1回だけ行う。ベースカラーとスカラーは `round-half-up(平均 × 255)`、法線は `round-half-up((n + 1) / 2 × 255)` とし、いずれも [0, 255] にクランプする。round-half-up の定義は第6.5節。
- tail は第7節の適合検証（ゴールデンベクタ）の対象外である。

## 6. 復号手順

入力は UV 座標 (u, v)、ラップ方式（U/V それぞれ repeat または clamp）、正規化 mip（normalizedMip、第6.2節）である。出力は8値の生出力（raw）と、それを後処理した PBR 値である。

### 6.1 グリッドのサンプリング（双線形補間）

寸法 (W, H)、チャンネル数 C のグリッドを (u, v) でサンプルする手順：

1. 座標のラップ：repeat の場合は u' = u − floor(u)（小数部）、clamp の場合は u' = min(max(u, 0), 1)。v も同様。
2. テクセル中心座標：p = u' × W − 0.5、q = v' × H − 0.5。x0 = floor(p)、y0 = floor(q)、fx = p − x0、fy = q − y0。
3. テクセル index の処理：repeat の場合は index を寸法で割った余り（負数も正に回す）、clamp の場合は [0, 寸法−1] に丸める。
4. **逆量子化は補間より前にテクセルごとに行う**：格納バイト q から f = 2q/255 − 1。
5. 4テクセルを fx, fy で双線形補間し、C チャンネルの値を得る。

### 6.2 入力ベクトルの構成と normalizedMip

- Fine グリッドを (u, v) でサンプルし C 値を得る。Coarse グリッドも同様に C 値を得る。
- 局所座標は **Fine グリッド側の位置** から計算する：rx = 2 × fract(p_fine) − 1、ry = 2 × fract(q_fine) − 1。ここで p_fine, q_fine は 6.1 の手順2で Fine グリッドについて計算したテクセル中心座標、fract(x) = x − floor(x)。
- 入力ベクトル x は次の順序で長さ 入力次元（= 2C + 4）：
  `[Fine の C 値, Coarse の C 値, rx, ry, normalizedMip, 1]`

**normalizedMip の定義**：

- normalizedMip は、サンプリング対象の mip レベルを [0, 1] に正規化した実数パラメータである。**0 が最も細かいレベル（元テクスチャの mip 0）** を表し、1 が mip チェーンの最も粗い端を表す。対応づけは `normalizedMip = λ / mipMax` とする。ここで λ は連続 mip レベルであり、描画側が UV の画面空間偏微分から `λ = max(0, (1/2) · log2(max(‖∂x(uv·S)‖², ‖∂y(uv·S)‖²)))` で求める（S は元テクスチャの寸法 `sourceSize`、‖·‖ は2成分ベクトルのユークリッドノルム）。結果は [0, 1] にクランプしてから入力する。
- **mipMax の決定**：マニフェストに任意フィールド `mipMax`（正の有限数）がある場合はその値を用い、無い場合は `mipMax = max(1, tailFirstMip − 1)` とする。読み手は、`mipMax` が存在するのに正の有限数でないマニフェストを拒否しなければならない。
- 値域は [0, 1] で、読み手はこの範囲外の値（および非有限値）を拒否してよい。省略された場合の既定値は 0 である。
- 学習と品質評価は normalizedMip = 0（mip 0 復号）で行われる。0 以外の値は、描画側が表示 LOD に応じて与えるための入力であり、適合範囲はゴールデンベクタの {0, 0.25, 0.5, 0.75, 1} で検証されている（第7節）。
- **現行世代アセットについての留保**：現行世代のアセットは、学習器・参照実装とも normalizedMip ≡ 0 固定で作成されており、マニフェストに `mipMax` は書かれていない。現行のランタイムは、`mipMax` 未設定のアセットに対して normalizedMip = 0 を供給する。上記の λ と mipMax の規約は、将来の mip 対応学習で作成されるアセットに対して効き始めるものであり、現行アセットの復号結果を変えるものではない。

### 6.3 MLP の前向き計算

- h1 = ReLU(w1 · x + b1)
- h2 = ReLU(w2 · h1 + b2)
- y = w3 · h2 + b3（線形、活性化なし）
- 正準の算術：入力ベクトル、各層の出力（活性化後）、最終出力は float32 の値として保持する（内積の途中経過の精度は問わない）。float64 で通し計算する実装との差は 1e-6 程度であり、第7節のゲート（1e-4）に対して十分小さい。

### 6.4 生出力の順序と PBR 後処理

生出力 y の8値は次の順序である：

`[ベースカラー R, ベースカラー G, ベースカラー B, 法線 X, 法線 Y, 粗さ, 金属度, AO]`

生出力はクランプされていない値である。PBR 後処理は次のとおり：

- ベースカラー：各成分を [0, 1] にクランプ。復号 BaseColor は**リニア空間**（`baseColorSpace = "linear-srgb"`）である。ホスト側で基準マテリアル表示等と比較・混在させる場合も同じ色管理（sRGB テクスチャはリニアへ変換してから照明に渡す）で揃えること。
- 法線：nx = clamp(y[3], −1, 1)、ny = clamp(y[4], −1, 1)。nx² + ny² > 1 の場合は両方に 1 / sqrt(nx² + ny²) を掛けて単位円盤上に縮める。nz = sqrt(max(0, 1 − nx² − ny²))。最後にベクトル (nx, ny, nz) を単位長に正規化する。
- 粗さ・金属度・AO：それぞれ y[5], y[6], y[7] を [0, 1] にクランプ。

### 6.5 量子化と丸め（書き込み側の約束）

丸めは **round-half-up** を使う。これは非負の x に対して `round-half-up(x) = floor(x + 0.5)` と定義され、JavaScript の `Math.round` と一致する（Python の `round()` の銀行家丸めとは異なるので、流用してはならない）。

- 潜在値の量子化：`q = clamp(round-half-up(255 × (clamp(f, −1, 1) + 1) / 2), 0, 255)`。式で書けば `q = clamp(floor(255 × (clamp(f, −1, 1) + 1) / 2 + 0.5), 0, 255)`。
- 逆量子化（読み手側）：`f = 2q / 255 − 1`。
- tail の格納時の丸めも同じ round-half-up を使う（第5.3節）。

## 7. 適合条件（ゴールデンベクタと閾値の二層構造）

適合の物差しは、サンプリング経路によって二層に分けて定義する。理由は、GPU のテクスチャユニットによるハードウェア双線形補間が、補間係数を厳密に計算する参照実装とは構造的に異なるためである（第7.2節）。

### 7.1 ゴールデンベクタ（数理的に厳密なサンプリング経路）

- ゴールデンベクタは、仕様から独立に生成した期待値の集合である。各ファイルは1プロファイル分で、次を含む：
  - `meta`：形式名 `VNM1-GOLDEN-v1`、プロファイル名、グリッド寸法（fine_size = [64, 64]、coarse_size = [32, 32]）、ケース数 286、ゲート値。
  - `weights`：w1, b1, w2, b2, w3, b3 を平坦な配列（行優先）で格納。
  - `fine_float` / `coarse_float`：量子化前の潜在グリッド（平坦配列、行優先・チャンネルインターリーブ）。
  - `fine_u8` / `coarse_u8`：6.5 の量子化を適用したバイト列。
  - `cases`：286 件。各ケースは `uv`、`wrapU`、`wrapV`、`normalizedMip` と、期待値 `expected_raw_float`、`expected_pbr_float`、`expected_raw_u8`、`expected_pbr_u8` を持つ。`*_float` は float グリッドをそのまま使った経路、`*_u8` は u8 に量子化→逆量子化したグリッドを使う経路の期待値。`expected_pbr_*` は `{raw, baseColor, normal, roughness, metalness, ao}` の形の後処理済み値。
- **適合ゲート**：float 経路で、全ケース・全出力成分について **最大絶対誤差が 1e-4 以内** であれば適合とする。このゲートは、補間係数を数理的に厳密に計算する実装（CPU 復号器、および GPU でも補間を自前計算する実装）に適用する。

### 7.2 ハードウェア補間を使う GPU 経路

GPU のテクスチャユニットによる RGBA8（rgba8unorm）の双線形補間は、サブテクセル補間位相を 8bit 固定小数点（1/256 刻み）で量子化する。そのため、テクセル中心に一致しない任意の UV では、補間重みの丸め誤差が隣接テクセルの勾配に乗って増幅され、MLP を通過した出力に最大で 1.8e-4 級の差が構造的に乗りうる。これは実装の誤りではなく、ハードウェア補間の仕様によるものである。したがって GPU 経路の適合は、次の2条件に分けて判定する：

1. **格子点（テクセル中心に一致するサンプリング）**：ハードウェア補間の位相量子化の影響を受けないため、厳密な閾値を適用する。実測では、合成グリッドの読み戻し検証で最大絶対誤差 7.2e-7 以下、実アセット（64×64 サンプル点）で最大 6.6e-7（PBR 後処理後でも 1.4e-5 以下）であり、1e-4 ゲートに対して十分な余裕がある。
2. **任意 UV（ハードウェア補間）**：補間量子化を前提とした閾値を適用する。実測の構造的上限は、デスクトップ GPU（Apple Metal-3）とモバイル GPU（ARM Valhall）の両方で **最大絶対誤差 1.81e-4**（RMSE は 1.8e-5〜3.0e-5）であり、任意 UV の GPU 経路のゲートはこの上限を踏まえて **2.0e-4** とする。最悪点はいずれも 0.1、0.2、0.333…、0.9999 のような非2進小数のサブテクセル座標に現れる。

なお、2進分数の格子点（テクセル中心に一致する座標）ではハードウェア補間でも参照と 1e-7 級で一致する。任意 UV で 1e-4 を僅かに超える差が出ることだけをもって、その GPU 実装を不適合としてはならない。逆に、格子点で 1e-4 を超える差がある場合は、補間量子化では説明できないため不適合の疑いとして扱う。

### 7.3 対象外

- tail チャンクはゴールデンベクタ適合の対象外である（第5.3節）。
- 品質ゲート（学習成果物の色・法線・スカラーの品質条件）は形式適合とは別の物差しであり、本書の範囲外とする。
